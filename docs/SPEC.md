# ContribHQ Specification & Architecture Guide

## 1. Overview
ContribHQ is an AI-powered developer onboarding and contribution management platform designed to match developers with targeted open-source and internal tasks using Gemini 2.5 Flash, PostgreSQL with Prisma, Express, and Next.js 14 App Router.

---

## 2. Data Models (Prisma)
- **User**: Represents a developer authenticated via GitHub.
  - `id`: Internal UUID primary key (`String @id @default(uuid())`).
  - `githubId`: Unique GitHub user ID (`String @unique`).
  - `username`: GitHub handle.
  - `name`: Display name.
  - `avatarUrl`: Profile picture.
  - `email`: User email.
  - `bio`, `techStack`: Onboarding profile data.
  - `createdAt`, `updatedAt`: Audit timestamps.
  - Relations: `activities` (`UserActivity[]`).

- **Issue**: Tracked GitHub repository issues eligible for contribution.
  - `id`: Internal UUID.
  - `githubIssueId`: BigInt representing GitHub's internal issue ID.
  - `repoOwner`: Repository owner/organization.
  - `repoName`: Repository name.
  - `issueNumber`: Issue number within repository.
  - `title`, `body`, `htmlUrl`: Issue metadata.
  - `subfield`: Categorization (`SubField` enum: `FRONTEND`, `BACKEND`, `FULLSTACK`, `DEVOPS`, `AI_ML`, `MOBILE`, `DOCS`, `OTHER`).
  - `difficulty`: Assessed difficulty (`Difficulty` enum: `GOOD_FIRST_ISSUE`, `BEGINNER`, `INTERMEDIATE`, `ADVANCED`).
  - `aiSummary`: Summary generated by Gemini 2.5 Flash.
  - `tags`: Array of string labels.
  - `isOpen`: Issue open/closed state.
  - Relations: `activities` (`UserActivity[]`).

- **UserActivity**: Tracks developer engagement with issues.
  - `id`: Internal UUID.
  - `userId`: Foreign key to `User.id`.
  - `issueId`: Foreign key to `Issue.id`.
  - `status`: Engagement status (`ActivityStatus` enum: `BOOKMARKED`, `IN_PROGRESS`, `SUBMITTED`, `MERGED`, `ABANDONED`).
  - `notes`: Developer's private notes or activity log.
  - `updatedAt`, `createdAt`.

---

## 3. Auth Boundaries & Security
- **Authentication**: Managed via NextAuth (`web/`) with the GitHub OAuth provider.
- **Identity Bridging**: NextAuth's `jwt` callback queries or provisions the database user and embeds the internal database UUID (`user.id`) directly into `token.userId` and the client session (`session.user.id`).
- **Client/Server Auth**:
  - The web frontend communicates with the Express backend using bearer tokens or session validation headers.
  - The Express backend relies on internal UUIDs for user activity tracking, keeping GitHub identifiers isolated to identity lookup.
- **Serialization Safety**:
  - Express server patches BigInt serialization: `(BigInt.prototype as any).toJSON = function () { return this.toString(); };` to eliminate serialization failures when serializing `Issue.githubIssueId`.

---

## 4. Ingestion Rules & GitHub API Constraints
- **Pagination Cap**: Ingestion runs are capped at **2 pages (max 60 items per run)** with `per_page: 30` to respect GitHub API rate limits and avoid timeout windows.
- **Label & State Filtering**: Issues must be in an open state and labeled with target contribution tags (e.g., `good first issue`, `help wanted`).
- **Enrichment Pipeline**:
  - Raw issue payload is parsed with Zod schemas.
  - Gemini 2.5 Flash categorizes the issue (`SubField`, `Difficulty`) and provides an onboarding summary (`aiSummary`).
  - Upserted into PostgreSQL using Prisma client singleton (`server/src/lib/prisma.ts`).
